# PixelProof — Risk-Based QA Strategy (v3.2)

## Purpose / scope

Exercise the fictional eCommerce journey from product administration to a customer's checkout, inventory reservation, order queue, admin login, shipping-label generation, label verification, dispatch, and delivery. Demonstrate QA planning, execution evidence, defect management and release gates across multiple test levels. **Nothing processes real money or carriers.**

## Test levels

| Level | Technique and examples | Evidence |
|---|---|---|
| Unit / business rules | SKU validation, pricing, decimals, quantities, stock, shipping, state-machine transitions, label escaping | Node.js tests (`tests/qa-coverage.test.js`) |
| API / contract | HTTP 200/400/401/402/403/404/405/409/413/415/422, payload schema, search, invalid content, admin auth | Node.js API tests |
| Integration | Checkout writes shared queue; stock reserved; admin sees order; label ref verifies dispatch; cancellation restores inventory | `tests/fulfillment.test.js`, `tests/commerce.test.js` |
| UI / responsive | Mobile admin controls, quick-view popup, safe areas, scripts/route structure | `tests/mobile-ui.test.js` static regressions; browser checks where available |
| End-to-end | Entire fictional customer-to-fulfillment journey in real browsers | Test cases `M-E2E-*` — require execution evidence |
| Accessibility | Keyboard, screen readers, WCAG 2.2 AA, 200% zoom | `M-ACC-*` planned; not certified |
| Security / privacy | Admin role, sessions, origin, XSS, no real PAN/CVC transmitted | Node tests and `M-SEC-*`; no formal pen-test |
| Performance / resilience | Mobile performance, concurrency, controlled errors, restart/persistence | `M-PERF-*` and `M-REL-*` planned |

## Prioritization and data

P0: overselling, order/payment integrity, admin authorization, irreversible dispatch, data loss. P1: workflow-obstructing defects, accessibility, serious mobile issues. P2: cosmetic/low-impact defects.

Tests use temporary isolated storage, fake emails at `example.com`, demo-only payment tokens, synthetic addresses and sample product IDs. Browser smoke does not perform successful purchases or alter inventory. The `qa-ci-results.json` report is generated by **actual executed Node tests** as part of `npm run check` and is not a human-edited pass summary.

## Minimum release gates

1. All automated unit/API/integration tests pass on the exact deployed commit; zero open P0/P1 functional regressions.
2. Critical multi-role end-to-end paths executed in real browsers, with order reference and screenshots / traces.
3. Physical iPhone Safari, Android Chrome, tablet and desktop cross-browser passes; no hidden or clipped CTAs.
4. Accessibility automated + manual review across customer, admin, modal and form states.
5. Security/privacy review including public demo credential boundaries and no real card use.
6. Defined load, concurrency, idempotency, persistence and restart tests passed before production claims.

**Current recommendation: CONDITIONAL / DEMO ONLY.** A passing test suite is not production sign-off. Public demo credentials, simulated payments and labels, and ephemeral Render Free storage are explicit limitations.

## Evidence and defect management

- Build QA JSON: `/qa-ci-results.json` (regenerated by the Render build; includes commit and actual results).
- Browser smoke: interactive Quality Bench (16 non-destructive checks, results from current visitor's browser only).
- Manual test inventory: `qa/manual-cases.json` (NOT RUN by default, with expected outcomes).
- Defects: `qa/DEFECTS.md` and Defects & Risks tab (confirmed issues separated from coverage gaps).
- CI execution: `https://github.com/sachintechpro/PixelProof/actions`.
- `npm run check` must fail on syntax or test regressions; no passing report is substituted if execution fails.

This is an educational, risk-focused QA demonstration rather than proof of full production qualification.
